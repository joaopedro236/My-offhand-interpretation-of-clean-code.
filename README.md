# 🇧🇷 Português

## Resumo dos capítulos

### Capítulo 1 — Código Limpo
Esse capítulo apresenta o que é o código ruim. Ele fala sobre os motivos pelos quais o código é ruim (prazo etc.), apresenta os benefícios do código bom e explica o que vai ter no livro.

### Capítulo 2 — Nomes Significativos
Nomes de variáveis que falem sobre si mesmas, nomes sem criptografia, nomes sem zoeira ou brincadeiras e nomes não muito longos.

### Capítulo 3 — Funções
Conceito de DRY (sem repetição), nomes de funções e quantidade de parâmetros, e o SRP (responsabilidade unica)

### Capítulo 4 — Comentários
Sem comentários muito grandes, comentários realmente significativos e não pode haver comentários em que a própria linha já se explica.

### Capítulo 5 — Formatação
Formatação clara. O código deve ser lido como um jornal.

### Capítulo 6 — Objetos e Estruturas de Dados
Estruturas claras.

### Capítulo 7 — Tratamento de Erros
O código deve ter tratamento de erros, evitando os IFs.

### Capítulo 8 — Limites
Limites de um item ou etc.

### Capítulo 9 — Testes Unitários
O código deve ter testes em todas as funções, senão o código não é limpo (isso eu não concordo, o código pode ser limpo sem testes).

### Capítulo 10 — Classes
Conceitos de DRY e SRP, e a classe não pode ser muito longa.

### Capítulo 11 — Sistemas
Ajuda a construir sistemas e etc.

### Capítulo 12 — Emergência
Design simples. Apresenta quatro regras:
1. Executar todos os testes.
2. Não ter duplicação.
3. Expressar claramente a intenção do programador.
4. Ter o menor número possível de classes e métodos.

### Capítulo 14 — Refinamento Sucessivo
Ajuda a refinar o código e etc.

### Capítulo 16 — Refatoração do SerialDate
Ele mostra um processo de refatoração de um código passo a passo.

### Capítulo 17 — Maus Cheiros e Heurísticas
Ele resume o livro todo, e sobre os maus cheiros é sobre os bugs: cada bug "fica um odor".

# 🇺🇸 English

## Chapter Summaries

### Chapter 1 — Clean Code
This chapter introduces what bad code is. It discusses why code becomes bad (deadlines, etc.), presents the benefits of good code, and explains what the book will cover.

### Chapter 2 — Meaningful Names
Variable names should describe themselves, avoid cryptic names, avoid jokes or inappropriate names, and should not be unnecessarily long.

### Chapter 3 — Functions
The concept of DRY (Don't Repeat Yourself), function names, and the number of parameter and SRP (Single Responsibility)

### Chapter 4 — Comments
Avoid overly long comments. Comments should provide meaningful information, and there should be no comments explaining what the code already makes obvious.

### Chapter 5 — Formatting
Clear formatting. Code should be read like a newspaper.

### Chapter 6 — Objects and Data Structures
Clear structures.

### Chapter 7 — Error Handling
Code should have proper error handling, avoiding IF statements.

### Chapter 8 — Boundaries
Boundaries of an item or etc.

### Chapter 9 — Unit Tests
Code should have tests for every function; otherwise, it is not clean (I disagree with this idea because code can be clean without tests).

### Chapter 10 — Classes
Concepts of DRY and SRP, and classes should not be excessively long.

### Chapter 11 — Systems
Helps us understand how to build systems and etc.

### Chapter 12 — Emergence
Simple design. Introduces four rules:
1. Run all the tests.
2. Eliminate duplication.
3. Express the programmer's intent clearly.
4. Minimize the number of classes and methods.

### Chapter 14 — Successive Refinement
Helps us refine code and etc.

### Chapter 16 — Refactoring SerialDate
Shows a step-by-step process of refactoring existing code.

### Chapter 17 — Smells and Heuristics
Summarizes the entire book. Code smells are signs of problems in the code: each problem leaves an "odor".
